Boundary Fluxes, Steady Columns, Moist Air & Scalar Hooks

Element and boundary fluxes

CanopyExchange.sensible_water_flux — Function
sensible_water_flux(sensible_heat, water_flux, vapor_enthalpy, tracers::NamedTuple = (;)) -> LeafFlux
sensible_water_flux(measure::Measure, sensible_heat, water_flux, vapor_enthalpy, tracers::NamedTuple = (;)) -> Exchange{typeof(measure)}

Element flux from sensible heat [W m⁻²], signed water flux [kg H₂O m⁻² s⁻¹], the specific enthalpy of the transported water vapour [J kg⁻¹] and passive tracers [mol m⁻² s⁻¹], all per m² of the element's own area. Without a measure the flux is a LeafFlux (per m² one-sided leaf area). The measure is passed as an instance (StemArea(), GroundArea() or a measure defined outside the package): an instance is isbits and works in broadcasts over GPU fields, a type does not.

The energy component is sensible_heat + water_flux * vapor_enthalpy: total energy including the enthalpy of the transported vapour. Do not add a separate latent-heat source when coupling the result to a conserved air energy budget. Evaluate vapor_enthalpy at the temperature of the donor surface (the leaf for transpiration; the air for condensation onto the surface), in the datum of the host energy budget, or shift the stream afterwards with shift_water_energy_datum. Kinetic energy carried by the transferred mass is excluded. Positive into the canopy air (photosynthetic CO₂ uptake is a negative co2, condensation a negative water_flux).

Examples

julia> f = sensible_water_flux(80.0, 4.0e-5, 2.5e6, (; co2 = -1.2e-5));

julia> (f.rates.energy, f.rates.tracers.co2)
(180.0, -1.2e-5)

julia> sensible_water_flux(StemArea(), 20.0, 1.0e-6, 2.5e6) isa StemFlux
true
CanopyExchange.sensible_stem_flux — Function
sensible_stem_flux(sensible_heat, tracers::NamedTuple = (;)) -> StemFlux
sensible_stem_flux(sensible_heat, water_flux, vapor_enthalpy, tracers::NamedTuple = (;)) -> StemFlux

Stem flux per m² one-sided stem area and second, positive from stem into air.

The first form is a dry woody surface: sensible heat [W m⁻² stem] and zero water. Its tracers are whatever the caller passes. To combine with a leaf flux that carries co2, the stem needs a co2 key too; passing (; co2 = 0.0) asserts that the stem exchanges no CO₂ (no stem respiration), it does not mean "not computed". The second form is sensible_water_flux(StemArea(), ...): stem evaporation [kg H₂O m⁻² stem s⁻¹] with mandatory vapor_enthalpy [J kg⁻¹], so the transported enthalpy water_flux * vapor_enthalpy is never silently omitted.

Examples

julia> s = sensible_stem_flux(35.0, (; co2 = 0.0));

julia> (s.rates.energy, s.rates.water, s.rates.tracers.co2)
(35.0, 0.0, 0.0)
CanopyExchange.surface_static_energy_flux — Function
surface_static_energy_flux(shf, lhf, evaporation, tracers::NamedTuple = (;)) -> FaceFlux

Upward face flux from SurfaceFluxes.jl static-energy outputs: sensible heat flux shf and latent heat flux lhf [W m⁻²], evaporation mass flux evaporation [kg H₂O m⁻² s⁻¹] and tracers [mol m⁻² s⁻¹], per m² ground area.

For fluxes computed by SurfaceFluxes.jl ≥ 1.0 (not prescribed ones), SHF = -ρ_sfc g_h ΔDSE + VSE_sfc E and LHF = LH_v0 E, with LH_v0 + VSE_sfc = Thermodynamics.enthalpy_vapor(T_sfc) + Φ_sfc. Hence shf + lhf is the moist static enthalpy plus surface-geopotential flux -ρ_sfc g_h ΔDSE + E (h_v(T_sfc) + Φ_sfc) relative to the Thermodynamics.jl datum, and it becomes the energy component. Conventional eddy-covariance c_p ΔT + L_v(T_air) E does not satisfy this datum without an explicit shift (shift_water_energy_datum). Tracer passing follows the rules of ExchangeRates: a zero value asserts a zero transfer.

Examples

julia> f = surface_static_energy_flux(60.0, 140.0, 5.6e-5, (; co2 = -1.5e-5));

julia> (f.rates.energy, f.rates.water, f.rates.tracers.co2)
(200.0, 5.6e-5, -1.5e-5)
CanopyExchange.shift_water_energy_datum — Function
shift_water_energy_datum(stream, delta_specific_energy::Real)

Add delta_specific_energy * water to the energy component of stream (an ExchangeRates or any Exchange record: element fluxes, face fluxes and volume sources alike); delta_specific_energy is in J kg⁻¹ H₂O, for example a reference-enthalpy offset h_v,target - h_v,source or a geopotential offset Φ_target - Φ_source.

Apply the shift to each water-carrying stream (every face flux and every element or volume source) before layer_tendency: interior faces then stay identical on both sides and telescope, and the column energy budget changes by exactly the shift times the water budget. Shifting a layer's net divergence afterwards drops the vertical gradient of the datum across the cell. Positional arguments only, so it broadcasts over host fields and GPU arrays.

Examples

julia> shift_water_energy_datum(face_flux(100.0, 2.0e-4), 5.0e4).rates.energy
110.0

Diagnostic steady-air flux profiles

CanopyExchange.layer_flux_increment — Function
layer_flux_increment(source::VolumeSource, geometry) -> FaceFlux

Integrate a bulk-volume source over the layer thickness: thickness * source, a face flux increment per m² ground area and second.

Examples

julia> s = VolumeSource(ExchangeRates(40.0, 1.0e-5));

julia> layer_flux_increment(s, LayerGeometry(2.5, 0.8)).rates.energy
100.0
CanopyExchange.steady_top_flux — Function
steady_top_flux(bottom::FaceFlux, source::VolumeSource, geometry) -> FaceFlux

Upward face flux at the layer top under zero air storage: bottom + thickness * source, so that layer_tendency(bottom, steady_top_flux(bottom, source, g), source, g) is zero to round-off. Bridges diagnostic zero-storage canopy models (ClimaLand big-leaf or diagnostic multilayer turbulence) and prognostic finite-volume columns.

Examples

julia> b, s, g = face_flux(20.0, 0.0), VolumeSource(ExchangeRates(15.0, 0.0)), LayerGeometry(2.0, 0.6);

julia> t = steady_top_flux(b, s, g);

julia> (t.rates.energy, layer_tendency(b, t, s, g).rates.energy)
(50.0, 0.0)
CanopyExchange.accumulate_steady_fluxes! — Function
accumulate_steady_fluxes!(faces, bottom::FaceFlux, sources, geometries) -> faces

Overwrite faces (N + 1 elements) from bottom upward across N layers with steady_top_flux and return faces. faces[end] is the emergent canopy-top flux bottom + Σ_k thickness_k * sources_k. sources and geometries must have identical first axes (OffsetArray and views are supported) and length(faces) == length(sources) + 1; otherwise a DimensionMismatch is thrown. Values are converted to eltype(faces).

Examples

julia> b = face_flux(10.0, 0.0);

julia> faces = accumulate_steady_fluxes!(Vector{typeof(b)}(undef, 2), b, [VolumeSource(ExchangeRates(6.0, 0.0))], [LayerGeometry(2.0, 0.5)]);

julia> [f.rates.energy for f in faces]
2-element Vector{Float64}:
 10.0
 22.0

See also accumulate_steady_fluxes.

CanopyExchange.accumulate_steady_fluxes — Function
accumulate_steady_fluxes(bottom::FaceFlux, sources, geometries) -> Vector{<:FaceFlux}

Allocate and fill a 1-based N + 1 steady face-flux profile from bottom to the canopy top (see accumulate_steady_fluxes! for the contract). The element type promotes bottom, the sources and the geometries, so a dual-valued source or geometry gives dual-valued faces. The element type is derived from the values (bottom, each source and each thickness(geometry)), so it accepts every input that accumulate_steady_fluxes! accepts: abstract or mixed geometry vectors, external geometry types and empty vectors. Pass a preallocated vector (for example an OffsetVector) to accumulate_steady_fluxes! for other face index axes.

Examples

julia> s = [VolumeSource(ExchangeRates(5.0, 0.0)), VolumeSource(ExchangeRates(8.0, 0.0))];

julia> faces = accumulate_steady_fluxes(face_flux(10.0, 0.0), s, [LayerGeometry(2.0, 0.5), LayerGeometry(1.5, 0.4)]);

julia> [f.rates.energy for f in faces]
3-element Vector{Float64}:
 10.0
 20.0
 32.0

Gas-volume moist-air tendencies

CanopyExchange.MoistAirTendencies — Type
MoistAirTendencies(rho_total, rho_water, rho_energy, tracers::NamedTuple = (;))
MoistAirTendencies(; rho_total, rho_water, rho_energy, tracers = (;))

Source tendencies per m³ gas volume and second for a host that conserves dry-air mass (S_ρd = 0):

  • rho_total [kg m⁻³ gas s⁻¹]: total moist-air mass source; equals rho_water (tracer mass is left out: the trace approximation, see ExchangeRates).
  • rho_water [kg H₂O m⁻³ gas s⁻¹]: total water mass source.
  • rho_energy [J m⁻³ gas s⁻¹]: total energy source in the host's datum.
  • tracers [mol m⁻³ gas s⁻¹]: passive molar tracer sources, kept nested so a tracer name cannot overwrite a host field.

Positive into the canopy air. Momentum, canopy drag and subgrid turbulent kinetic energy are excluded. Host adapters own the conversion to temperature and humidity tendencies. Same precision policy and componentwise algebra as ExchangeRates.

Examples

julia> m = MoistAirTendencies(4.0e-5, 4.0e-5, 150.0, (; co2 = -1.0e-5));

julia> (m.rho_total, m.rho_energy, m.tracers.co2)
(4.0e-5, 150.0, -1.0e-5)

See also moist_air_tendencies.

CanopyExchange.moist_air_tendencies — Function
moist_air_tendencies(tendency::VolumeSource, gas_fraction = one(eltype(tendency))) -> MoistAirTendencies

Divide a bulk-volume tendency [per m³ bulk canopy volume and second] by the gas volume fraction gas_fraction [m³ gas m⁻³ bulk] to obtain source tendencies per m³ gas volume (MoistAirTendencies).

Contracts:

  • gas_fraction is constant in time (∂ₜ ε_gas = 0), lies in (0, 1] and has the floating-point type of tendency; a nonfinite value, a value outside that interval or a nonfinite derivative component throws an ArgumentError.
  • Dry-air mass is conserved (S_ρd = 0), so rho_total == rho_water == water / gas_fraction; rho_energy = energy / gas_fraction, and every tracer is divided by gas_fraction. Leaving tracer mass out of rho_total is the trace approximation (about 1.3 % of the water mass source for daytime CO₂ uptake, and dominant when transpiration is near zero; see ExchangeRates).
  • Each component is divided (not multiplied by the inverse), which keeps exact identity at gas_fraction == 1. Ratios between tracers are kept exactly for ±1:1 stoichiometry (equal magnitudes) and to rounding otherwise.
  • Apply any reference-enthalpy or geopotential shift to the individual streams (shift_water_energy_datum) before layer_tendency, not here.
  • Positional arguments only, so it broadcasts over host fields and GPU arrays.

Examples

julia> v = VolumeSource(ExchangeRates(180.0, 3.6e-5, (; co2 = -1.8e-5)));

julia> m = moist_air_tendencies(v, 0.9);

julia> (m.rho_total, m.rho_water, m.rho_energy, m.tracers.co2)
(4.0e-5, 4.0e-5, 200.0, -2.0e-5)

Scalar hooks (public)

The defaults are exact for plain floating-point numbers. The package extension CanopyExchangeForwardDiffExt (loaded with ForwardDiff 0.10 or 1.x) defines them for ForwardDiff.Dual; another number type with derivative information takes part by defining the same five methods.

CanopyExchange.primal_type — Function
CanopyExchange.primal_type(::Type{T}) -> Type

Floating-point type that carries the value of scalar type T. The default returns T; a derivative-carrying number type returns the floating-point type of its value (for ForwardDiff.Dual{Tag,Float64,N} this is Float64).

The precision policy compares primal_type of every scalar that meets in a record or kernel: they must agree and be an AbstractFloat.

Examples

julia> CanopyExchange.primal_type(Float32)
Float32
CanopyExchange.primal — Function
CanopyExchange.primal(x)

Value of scalar x without derivative information, in the units of x. Used for comparisons in validity checks (layer thickness, area densities, gas fraction) and for hashing, so neither depends on how a number type compares derivative components.

Examples

julia> CanopyExchange.primal(2.5f0)
2.5f0
CanopyExchange.all_finite — Function
CanopyExchange.all_finite(x) -> Bool

Whether the value and every derivative component of scalar x are finite. Used by valid_exchange and by the geometry and gas-fraction checks.

Examples

julia> (CanopyExchange.all_finite(1.5), CanopyExchange.all_finite(NaN))
(true, false)
CanopyExchange.exact_zero — Function
CanopyExchange.exact_zero(x) -> Bool

Whether the value and every derivative component of scalar x are zero (either sign). area_source uses it for the empty-layer rule: an area density that is an exact zero contributes an exact zero, while a zero value with a nonzero derivative component keeps the right derivative rate.

Examples

julia> (CanopyExchange.exact_zero(-0.0), CanopyExchange.exact_zero(1.0e-12))
(true, false)
CanopyExchange.scalar_equal — Function
CanopyExchange.scalar_equal(compare, x, y) -> Bool

Whether scalars x and y are equal under compare (== or isequal) in value and in every derivative component; a plain number has zero derivative components. Record equality (==, isequal) is built on it, so it does not depend on how a number type defines == (ForwardDiff 0.10 compares values only, 1.x also partials). The default is compare(x, y).

Examples

julia> (CanopyExchange.scalar_equal(==, -0.0, 0.0), CanopyExchange.scalar_equal(isequal, -0.0, 0.0))
(true, false)
